# Security policy

## Supported versions

Security fixes are provided for the latest `v1` release line.

## Reporting a vulnerability

Use GitHub private vulnerability reporting when available. Otherwise, contact the maintainer through the private address listed on the maintainer's GitHub profile and include:

- affected version;
- impact;
- reproduction steps;
- suggested mitigation, if known.

Do not include live credentials. You should receive an acknowledgment within seven days.

## Scope

Security-sensitive areas include privileged GitHub workflow behavior, token permissions, comment modification, trusted configuration loading, secret redaction, and path traversal.
